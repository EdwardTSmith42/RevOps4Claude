# Source-to-content transformation

A source can play three different roles in new content. It can be the **subject** the writer is discussing, **evidence** supporting the writer's argument, or a **catalyst** that helps the writer discover an idea of their own. The role determines how much of the source should remain visible in the concept or draft.

Infer the role from the user's intent. Requests to respond, react, explain, or comment usually make the source the subject. Requests to support an existing claim usually make it evidence. Requests for inspiration, new concepts, or ideas for the user's own business or audience usually make it a catalyst. Ask only when the difference would materially change the result and the request does not resolve it.

When the source is a catalyst, traceability and dependence are different things. The reasoning should still have an honest path back to the source, but the eventual reader should not need to know the source, speaker, story, or original framing. Extract the portable idea first, then develop it through the writer's own worldview, audience, experience, business, tensions, and adjacent beliefs. Removing names is not enough. The writer's lens should add intellectual work the source did not already package.

The relationship between the writer and the source matters. If the source is the writer's own notes, interview, draft, or prior work, preserve distinctive language and genuine experiences when they strengthen the concept. If it comes from someone else, use it to stimulate thinking without casually transferring that person's personal story, signature phrasing, or named framework into the writer's mouth. Some external ideas are broad enough to become invisible catalysts; other concepts remain stronger and clearer when the source stays visible as evidence. Keep that boundary legible without turning every inspired idea into source commentary.

Before returning catalyst-based concepts, apply four tests:

- **Source removal:** Would the concept still make sense and feel complete if the reader never encountered the source?
- **Writer ownership:** Could this writer credibly develop the premise from their own knowledge and point of view?
- **Audience value:** Does the concept connect to something this writer's audience actually cares about?
- **Contribution:** What has the writer's lens added beyond a generic paraphrase of the source?

Never invent first-person experience to manufacture ownership. When a concept would benefit from a personal example that is not available, name the opening for the writer to fill rather than fabricating the story.

Extraction and generation have different fidelity requirements. Extracted nuggets, quotations, frameworks, and summaries stay faithful to what the source contains. Content concepts derived from those artifacts become self-sufficient and writer-owned by default when the source is acting as a catalyst. Explicit source-facing requests override that default.
