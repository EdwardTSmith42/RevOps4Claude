# Core Transformation — canonical output shape

Use this shape for `modes/core-transformation`. The mode's central deliverable is a crisp FROM/TO articulation plus the non-obvious insights that make the transformation specific rather than generic.

## Shape

```markdown
# Transformation Analysis: [Offer or Business Name]

## FROM / TO

**FROM:**
- → [current state 1 — specific, grounded, named]
- → [current state 2 — often the felt pain]
- → [current state 3 — often the identity the prospect is stuck in]

**TO:**
- → [desired state 1 — specific, concrete]
- → [desired state 2 — the felt relief or capability]
- → [desired state 3 — the identity they become]

---

## Key Benefits

1. **[Benefit name]:** [concrete description — what the prospect gets, measurably where possible]
2. **[Benefit name]:** ...
3. **[Benefit name]:** ...
4. **[Benefit name]:** ...
5. **[Benefit name]:** ...

---

## Non-Obvious Master-Level Insights

*These are the aha-moments — the things the offer owner hadn't articulated, or the angles the prospect hasn't considered. Not the front-of-the-brain material.*

### 1. [Insight name / headline]
- [The non-obvious observation]
- [Why it matters — what it reveals about the transformation]

### 2. [Insight name]
- ...
- ...

### 3. [Insight name]
- ...
- ...

Three insights minimum. Each one should make the reader say *"huh, I hadn't thought of it that way."* If an insight reads as restatement of something already obvious from the input, it's not a master-level insight — cut it and look harder.

---

## What the Experts Say

*Relevant named-framework touchpoints. Brief — one sentence per expert. Reference, don't lecture. See `references/audience-insight-influences.md`.*

1. **[Named expert] principle/framework**: [how it applies to this specific transformation]
2. **[Named expert]**: ...
3. **[Named expert]**: ...

---

## Potential Challenges to the Transformation

*Audience limiting beliefs that will resist the transformation even when it's offered cleanly. Each paired with a brief counter-framing (not a full dislodge — this is the audience-side of the analysis). See `references/buyer-psychology-beliefs.md`.*

1. *"[Stated limiting belief]"*
   - **Counter-framing:** [how the transformation's structure addresses this]

2. *"[Stated limiting belief]"*
   - **Counter-framing:** ...

3. *"[Stated limiting belief]"*
   - **Counter-framing:** ...
```

## Key rules

- **FROM/TO is the headline.** Everything else supports it. The FROM/TO statement should be sharable as a standalone artifact — if someone only reads that section, they should understand the transformation.
- **Arrow-bullet format ("→") for the FROM/TO states.** Preserved from the source — the multi-line arrow structure lets each dimension of the transformation stand on its own line without tabular overhead.
- **3-layer FROM/TO minimum.** At least one circumstantial line, one felt-experience line, one identity line. The transformation isn't complete if it only moves the prospect between states of circumstance or between states of feeling — durable transformations shift identity.
- **Non-obvious insights pass the "huh" test.** If the insight reads as restatement of something already obvious, cut it. *"The offer saves time"* fails the test. *"The rapid-results window isn't about speed — it's about preventing perfectionism by creating a success-momentum spiral"* passes.
- **Anti-cliche self-check.** Before shipping, read every line and ask: *"Is this something any competent AI would produce, or does it specifically show through the input?"* If the line could apply to any offer, it's a cliche and needs to be rewritten against the specifics. (This is the source prompt's original move: *"Can I return results that are less cliche?"* Preserve the discipline.)
- **Experts cited briefly.** One sentence per expert. The expert reference points at a tradition. The insight is the work. Do not pad with biography.
- **Challenges paired with counter-framing, not full dislodge.** This mode surfaces the challenges. `modes/limiting-beliefs` does the full dislodge work. Don't duplicate.

## What this template is not

- **Not a content plan.** The source prompt included "Ways to Communicate the Transformation" and lead-magnet suggestions. Those are content-strategy work and belong in a future content-strategy skill. This mode stops at articulating the transformation.
- **Not a sales copy draft.** The output is source material for sales copy, not sales copy itself.
- **Not a generic before/after.** The specificity and non-obvious insights are the whole point. A vague before/after is a failed transformation articulation.
